# ferrite-ui-xl — change log and subsystem notes

Moved out of CLAUDE.md on 2026-11-15. Dated, detailed notes per subsystem (design, invariants, board measurements). Newest work first in each bullet; `grep` for a symbol to find its note.

**GPS (2026-11-20):**
- The tablet's u-blox G6010 (UBX-G60xx, ROM 7.03) is on UART1 and needs only power: MAX77686 LDO9 1.8 V (I/O), 10 ms, LDO18 2.8 V (antenna LNA); it sends NMEA at 9600 baud by itself. HAL (exynos_4412_rs README "GPS"): `drivers::g6010` (`power_on`/`power_off`/`setup_uart`), `Cmu::set_uart_clock` (`sclk_uart1` = MPLL / 8 = 100 MHz), `Uart::configure` (8N1, `UBRDIV`/`UFRACVAL`), `Max77686::disable_ldo`, `nmea` (sentences, checksum, `RMC`/`GGA`/`GSV` in fixed point), `UartRx::try_read` (non-async), `gps_test`. Facts only were taken from the vendor kernel's GPL `g6010.c` / `mach-mehmet.c`.
- Syscalls 0x90..=0x94 (`ferrite_core::gps` ↔ ferrite-ui `lib/gps.fl` ↔ both `platform.rs`): power, state (`GPS_OFF`, `GPS_NO_DATA` = silent 3 s, `GPS_SEARCHING`, `GPS_FIX` = a valid position ≤ 3 s old), `GET(field)` (lat/lon degrees × 10^7, altitude dm, speed km/h × 10, course, satellites used/in view, HDOP × 100, fix age, quality), `TIME` (UTC Unix seconds from the receiver), `TEXT(field)` (`"41.0123456"`, position). `GpsBackend` per board; `GpsData::state` / `field` / `text` shared (tests in `gps.rs`).
- exynos (`bsp/exynos4412/src/gps.rs`): off at boot; the first power-on sets UART1 up and its receive interrupt (CPU0, the HAL's 2 KiB ring ≈ 10 s of sentences); `poll` from `frame_end` and from each syscall; the PMIC on I2C0 from CPU0, as audio. A program that ends leaves the receiver as it was. `/api/status` `"gps"`: state (-1 never powered), satellites, position. Sim: `FERRITE_SIM_GPS=LAT,LON[,ALT_M]`, else always searching.
- Example `examples/exynos4412/gps` (app `com.example.gps`). Board 2026-11-20, the tablet where it sat (gps_test there earlier: no fix, 2 satellites in view): a fix within 2 minutes of power-on, 7 of 10 satellites, HDOP 1.4; time and position on the screen twice a second.
- Found on the way, fixed in ferrite-ui `ferrite_lang.py`: the codegen's current-target tracking (`_current_target`, which skips `W_TARGET_S` for a widget already targeted) carried the then branch's target into the else branch of an `if` and of `?:`, so `else { x.text = ... }` wrote whichever widget was targeted before the `if`. Also after `&&` / `||` (the right side may not run). Golden and the testdata generators unchanged.


**writefs hot swap, bridge restart (2026-11-18):**
- `writefs` used to end in `P::reset()` (`FsWriteComplete`), on every board. Now the runtime reads the running image's syscfg at `FsReady` (`fs_old_cfg`) and, when the verified new image has the same one, swaps it in (`Runtime::hot_swap`): `render::wait_idle`, children dropped, the FS mounted again, `FontList::reset_to_embedded` + `ImageList::clear_for_new_fs` (an epoch the render context's copies follow in `sync_from`: the same ids name other resources now), `P::fs_replaced` (exynos: `flash::save_if_dirty(true)`), then `main` from scratch as at boot (argument 0). Other pool sizes still restart (they are sized once, at boot). exynos caches by flash address follow `flash::generation` (bumped by every write): `compose` image textures (`ImgTex::generation`) and the glyph atlas (emptied on a new generation), as the tiled pictures and `renderer::picture_addr` already did. `ferrite_cli` says "the device runs the new image". Board: the tablet image with a changed label, written twice over `tcp://`: no restart (uptime kept), the new text shown, settings kept.
- `ferrite_cli -p tcp://… restart` did nothing: the CLI sends `0x18` and closes at once, `bridge_serve` ended the session on the close, the runtime went back to UART2 and the byte stayed in `bridge::RX` until the next session dropped it. The session now stays after the client's close until the runtime has taken every byte and both rings stayed empty 100 ms (`BRIDGE_CLOSE_QUIET`, at most `BRIDGE_CLOSE_WAIT` 2 s). Board: 7/7 restarts.
- `/api/status` has `"settings"` (live UTC offset, brightness, volume, NTP state and age).

- `system/settings.txt` (lower case; `ferrite_core::settings`, format in its doc): `utc_offset=+03:00`, `ntp=` (default `pool.ntp.org`, `off`), `brightness=`, `volume=`, `app=` (the app to start at boot, `docs/apps.md`; set by `POST /api/apps/boot`, cleared when that app is removed). Read at boot (`bsp/exynos4412/src/settings.rs` `load`, after `storage::init`): the backlight in `Platform::boot` (else `BOOT_BRIGHTNESS`), the volume on the codec before the runtime. Written by `save_if_due` from `storage::sync` once a change has settled 2 s (`SAVE_AFTER_MS`; any change on `force`: restart, standby, power-off). Changes: the VM's `setBrightness` / `setVolume` (`note_brightness` / `note_volume`; only a different value counts) and `SYS_SET_UTC_OFFSET`. The sim keeps them for the run only (no file: golden runs stay the same).
- The RTC keeps UTC. `RtcImpl::read_time` / `set_time` shift by `settings::utc_offset()` (`DateTime::to_unix` / `from_unix` / `shifted`), so `rtcRead`, `rtcWrite` and the protocol's set-time (`ferrite_cli settime`: the PC's local time) are local time; `read_utc` is the chip's.
- NTP (`net/ntp.rs`, a CPU3 task in `GROUP`): DNS (embassy-net `dns`, servers from DHCP) + one UDP socket (`udp`; `SOCKETS` 8 → 10), SNTP v4, 3 tries × 3 s, the reply checked (originate = our nonce, mode 4, stratum 1..15, LI ≠ 3), half the round trip added. Once DHCP gives an address, then every 6 h, after a failure every minute, or when a program asks (`SYS_NTP_SYNC`, an atomic polled each second). The time goes to CPU0 through `rtc::set_from_ntp` (secs + `systick::millis` at that second, a generation): CPU0's next RTC read sets the chip once and every `PmicRtc` takes it as its base.
- Syscalls 0x50..=0x56 (`settings::SYS_*` ↔ ferrite-ui `lib/device.fl` ↔ both BSPs' `platform.rs`): UTC offset get/set, NTP sync / state / age / server, the saved volume (`ui.fl` takes it when the program argument has none, i.e. at boot). Tablet Settings: a "Date & time" card (time zone in 30 min steps, Sync now, NTP state, local time); the About card is half as wide.

**Rich text (2026-11-15):**
- `FLAG_RICH_TEXT` (bit 8, was `FLAG_DIRTY_B`), prop `rich_text` (0x38, `caps.rich_text`): labels / buttons read their text as an HTML subset (`rich.rs`, docs `ferrite-lang.md` "Rich text"): `<b>`/`<strong>`, `<i>`/`<em>`, `<u>`, `<font color>` (#RRGGBB, #RGB, names, RGB565 numbers; 8 levels), `<br>`, entities; other tags left out, a `<`/`&` that starts none is text. Parsed while laying out (`rich::Cursor`, a copyable place + open tags): nothing stored, so the scene, commits and `dl_key` (flags + text bytes) see one string as before.
- Bold / italic = font families: V3 header bytes 8..10 = the bold / italic / bold italic variants' font ids (`Font::variant`; bold italic falls back to bold, then italic; none = the font itself), written by `ferrite_build` from the project's font entries (`"bold"`, `"italic"`, `"bold_italic"` = font names). `FontList::find_or_load` loads a font's variants with it (the render side only gets loaded fonts).
- Layout (`render::rich_label`, `Rich`): `Rich::wrap` breaks as `Font::wrap_line` (test `render::rich_tests::plain_text_wraps_the_same_as_rich_text`), lines in the regular font's line height, alignment by the line's width. `label_lines`' callback takes `LabelItem`: `Text` per run of one font + colour (a 120-byte buffer; a full one continues at its pen: same pixels), then `Rule` per underline (after the line's text: an opaque glyph cell drawn later would cover it; y = baseline + max(1, lh/12), max(1, lh/20) thick). Plain labels take the old path unchanged. exynos compositor: runs in their colours, rules as `solid`s; `renderer.rs`' label sprite key hashes the flag.
- Tools (ferrite-ui): `ferrite_rich.py` (Python copy of the parser, Designer preview: runs, variants, colours, underlines; one line per `<br>`, no wrap), Designer `rich_text` box + double-click a font for its variants; `ferrite_build` rejects `rich_text` without `caps.rich_text` and variants on non-V3 fonts.
- Sim (Segoe UI 26 regular/bold/italic/bold italic + a font without variants; wrapping, centred / right-aligned, nesting, entities, `<br>`): one frame in plain / DL verify / areas / play. Board: the same frame (±2 per channel: the BMPs' 565→888 rounding) in render modes 0–3 (`POST /api/rcore?mode=`, the program re-rendering every second). Golden 13/13 default and `--dl`.

**V3 fonts (2026-11-15):**
- V1/V2 font resources store glyph metrics in 7 bytes (offset u16, w/h/advance u8, offsets i8): at 96 DPI they end around 130pt (Ubuntu 130pt: `"` has yOffset −130; a 2bpp ASCII set passes 64 KB of bitmap). V3 (magic `00 03`, 12-byte header with `y_advance` u16 + font_id + bpp + three variant font ids (rich text, below) + 0, 14-byte glyphs: offset u32, w/h/advance u16, offsets i16; bitmap as V1/V2) lifts both. `GfxGlyph` is the wide form for every version (`font::Header::read` tells them apart; a V1 font of 0x0300 glyphs is not taken for V3: V3 needs bpp 1/2 in byte 7 and its tables to fit). `line_height`, `char_width(_cp)` and `draw_char` return u16.
- Tools (ferrite-ui): `caps.font_v3` on `exynos4412-xl` (build-time only, no CAPS bit). `ferrite_build` repacks every font of such a project as V3 (`ferrite_font_converter.to_v3`: same glyphs and bitmap, so the same pixels) and rejects a V3 font for other devices; the Designer generates V3 for them; `ferrite_font_converter.py resource --v3`; the V1/V2 range errors name `--v3`. The converter imports freetype-py only to rasterize (`ferrite_build` uses its `parse_header` / `read_resource`).
- Golden 13/13 default and `--dl` with every example font as V3 (`setup.img` rebuilt: its fonts are V3 now). Test `font::tests::v3_fonts_hold_wide_metrics` (300 px glyph at bitmap offset 70 000, yOffset −200, line height 310). Sim: Ubuntu 130pt Turkish 2bpp (233 KB), 200pt digits, 130pt 1bpp: same frame in plain / `FERRITE_SIM_DL_VERIFY` / areas / play.

**WiFi join with a Zyxel EX3501 (2026-11-15):**
- Symptom: `wifi join ERROR Wpa(RsnMismatch)`, then `Disconnected { event: 6, reason: 15 }` (4-way handshake timeout) on every later try until a restart; a Mi Box failed with the same modem. Cause: the modem (MediaTek, one SSID on 2.4 + 5 GHz, PSK + FT-PSK, MFP capable) sends its RSN element **without** a PMKID list in probe responses (`301e…`) and **with** one in beacons and in message 3 (`302e…0100 <PMKID> 000fac06`), and changes the PMKID over time. The HAL's supplicant compared message 3's element byte for byte with the scan's (whichever frame came first), so a scan that kept the probe response's element failed after a correct MIC.
- Fix (HAL `wpa.rs`): `same_security` compares the parsed fields (version, group, pairwise, AKMs, capabilities, group management cipher) and skips the PMKID list, as wpa_supplicant's `wpa_compare_rsn_ie`; a changed suite / capability / cut element is still `RsnMismatch` (tests `pmkid_list_is_not_compared`, `message_3_with_the_beacon_element_is_taken`). `Bcm4334::connect` now `disassociate`s (`WLC_DISASSOC` 52, reason 3) after any failed join: the half-open association was what made the next tries time out.
- Diagnostics kept: `GET /api/wifi` (scans, target, each BSS's elements as seen per frame kind, the last mismatch's expected / message 3 elements), UART `wifi seen …` / `wifi joining …` lines. HAL tests don't build for the host as a crate (its panic handler): compile `crypto.rs` + `wpa.rs` in a scratch lib with `rustc --edition 2024 --test`.
- Board: 6 restarts in a row, each joined on the first scan (ch 9, 22–37 s to HTTP up), 0 mismatches. uart_boot (same supplicant) rebuilt and flashed to the boot partition (`fastboot flash boot`, partition `boot`, device `SMDKEXYNOS-`): 7 boots polled every second, each with uart_boot on WiFi at 3–9 s and ferrite up at 13–20 s, 0 mismatches; that uart_boot also has the 2026-11-13 autoboot fix (polling no longer holds it).

**Differences from ferrite-ui (read these first; the sections below are inherited and still describe ferrite-ui where they disagree):**
- Targets: `bsp/exynos4412` and `bsp/sim` only. The sim is always 1280×800 with a readback framebuffer.
- Always compiled (no longer features): `layers`, `multi_program`, `perf`, `fast_vm`, `superops`, `render_cache`, `wide_obj`, `wide_code`, `pool_large`, `audio`. Remaining core features: `host`, `mock`, `external_alloc`, `jpeg`.
- Removed: `epaper`, `sdcard`, `sdboot` (+ `sdcard.rs`, `fat.rs`, `sdboot.rs`), the write-only anti-aliasing path (`LcdBackend::AA_UNDERLAY`, `Underlay`, `set_underlay`), the sim's `no-readback`/`tablet` features, the buffered render mode (dirty rendering only: `render_buffered*`, `RenderMode`, `FLAG_DIRTY_A/B` → one `FLAG_DIRTY`, one prev rect per widget; image header flags bit 0 and project.json `render_mode` are ignored).
- Compiler, `.fl` library and Designer are NOT in this repo: they stay in ferrite-ui (single source). Examples include `../ferrite-ui/lib`; `sim.bat` uses `%FERRITE_UI%` (default `..errite-ui`). XL-only bytecode is enabled through device caps (`caps.*`).
- Native flex: `flexLayout(box)` compiles to `FLEX_LAYOUT` (0xDB, `vm_flex.rs`) for devices with `caps.native_flex` (`CAP_NATIVE_FLEX`); XL examples use the `exynos4412-xl` device profile (ferrite-ui `tools/devices`). `FLEX_AUTO` (128) containers are laid out by the firmware (`ObjPool::flex_pending`, flushed before render passes and before VM reads of loc/size). `runtime::flex_tests` compares both with lib/flex.fl / explicit calls; regenerate its programs with `python ferrite-core/testdata/flex/gen.py` after changing flex.fl.
- Drawing goes through `canvas::Canvas` (`LcdImpl` = immediate). Display lists (`dl.rs`): with `dl::ENABLED` (sim `FERRITE_SIM_DL=1`, exynos `POST /api/dl?on=1`, `golden.py --dl`) `render::draw_body` draws through `ObjPool::render.dl_cache`, keyed by `render::dl_key` (a hash of everything `draw_widget_body` reads: anything new it reads must go into the key). A look is recorded on its second sighting against the whole screen, then replayed per clip rect (`List::replay_clipped`). `dl::VERIFY` (sim `FERRITE_SIM_DL_VERIFY=1`, always with `golden.py --dl`) re-records every hit and panics on a stale list. `on_paint`: the VM's drawing opcodes go through `Vm::draw_op` (`canvas!`: the screen, or `ObjPool::render.paint_rec` while `painting`); with display lists `Vm::run_paint` records each widget's `on_paint` (`record_paint`), replays it where it was drawing and keeps it in `render.paints`. Dump (`render::dl_dump`, from the key each widget last drew with, `render.drawn_keys`): exynos `GET /api/dl[?id=N]`, sim `--dl-dump` (`dl_MS.txt` beside each dumped frame) and right click on a widget (stderr). Must stay pixel-identical (golden hashes are shared by both modes).
- Display list encoding (`dl.rs`, 2026-11-13): a `List` is one `Vec<u32>` stream, like the VM's bytecode but word-aligned and without varints: a header word (opcode bits 0-7, a small argument bits 8-15, usually the colour bits 16-31), 16-bit arguments two to a word, `i32`s a word each, slice data (pixels, coverage, points) inline, zero-padded to a word and read in place (`Offset` is `repr(C)`). Layouts in `dl::code`; `List::ops` decodes into the borrowing `Op<'_>` (replay, dumps, tests); `List::len` = calls. Recording writes each call with one capacity check (`List::call`/`put_bytes`). Was a fixed-size `Op` enum (28 B a call on the board, 32 on the PC). Test `dl::tests::every_call_decodes_to_what_was_recorded`; golden 13/13 default and `--dl`, `--play` identical to `--plain`. Board, play mode (`perf/merge/dl-words-*.json`): Monitor stress 12.8 → 5.4 KB a frame (same ~455 calls), CPU2 job unchanged, CPU0 render 32.1 → 33.1 ms/s (+3%, likely code layout: normal mode moved too); idle tablet home 165 → 146 KB (pixels dominate), CPU0 unchanged.
- Images and text in display lists by reference (2026-11-13): `Canvas::draw_image(img, flash, x, y)` and `Canvas::draw_text(font, flash, text, x, y, fg, bg) -> x_end` (defaults = `Image::draw` / `Font::draw_str` now; `render.rs` images, labels, fields and the VM's `drawImage`/`drawText` go through them; keyboard, error and boot screens still draw on the LCD). The `Recorder` writes `IMAGE` (`Image::data_addr`, x|y) and `TEXT` (font id + `Font::bitmap_addr`, colours, pen, UTF-8 bytes) instead of their pixels / coverage rows, and leaves out what would draw nothing (`Image::visible`; text: `draw_str`'s culling via `for_each_glyph`, which also gives the returned pen x). Replays take a `dl::Refs` (`Ctx::refs()` = that context's `images`/`fonts`/`flash`): it looks the image up by address (`ImageList::find_addr`) / the font by id + bitmap address and calls `draw_image` / `draw_text` on the target, so a replay into another recorder passes the reference on and the decoding happens where the list is played (CPU2 in play mode, from the render context's synced copies). A reference the replaying side doesn't hold draws nothing and counts `dl::REF_MISSES` (debug assert; sim `sim: dl ref misses N`, none in golden). Tests `dl::tests::text_is_recorded_by_reference` (+ the decode test); golden 13/13 default and `--dl`, `--play` identical to `--plain`. Sim play lists: tablet scenes 690–1380 → 3.5–6.6 KB a frame.
